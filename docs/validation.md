# Plex R3 beta validation

Validated locally on 2026-11-05. Source baseline: `46e7a0cd4df1c31ebab036e4050d6657083ffc12`. These checks support the published [v0.2.0-beta.1 release](releases/v0.2.0-beta.1.md); the linked record identifies the exact live version and artifacts.

## Passed

- Standard-library checks: bilingual direction/language, unique IDs, local links, CSS assets, approved original SVG/PDF hashes, delivery-SVG hashes and absence of font dependence, pinned original font hashes, web font source mapping/notices, deployment exclusions and deterministic kit/checksum consistency. Node syntax checks and `git diff --check` pass.
- **72 browser cases**: Chromium 156.0.8078.74, Firefox 155.0 and WebKit 26.6, each covering English/Arabic × 320/390/1440 px × System/Light/Dark/Black. The existing production CSP was applied unchanged. Real loaded fonts, Regular body text, correct heading weights, resolved appearance, decoded images (including lazy wallpapers), no horizontal overflow and no page errors were checked. **432 transparent 1600 px PNG exports** completed, with permitted background selectors and colour-copy status/fallback exercised.
- **36 accessibility cases**: all three engines × English/Arabic × 320/1440 px × Light/Dark/Black. Axe-core 4.14.0 reported **zero violations and zero incomplete findings** for the selected WCAG 2 A/AA, 2.1 AA, 2.2 AA and best-practice rules. Space opens the appearance picker, arrow keys change the selected native radio, Escape closes it and restores focus, keyboard traversal reaches the next action, the skip link focuses main content, and the Type heading clears the sticky header. WebKit uses Safari's default Option-Tab link traversal; no browser preference was changed.
- **72 responsive-navigation cases**: Chromium/Firefox/WebKit × English/Arabic × 320/390/768/1024/1025/1440 px × Light/Dark. Closed, open and nested appearance-panel states had zero axe violations. Keyboard open/traversal/Escape, nested Escape handling, section-target focus, outside dismissal, focus leaving the panel, mobile/desktop resizing and 320 px-tall screens passed. Both languages remained usable without JavaScript in all three engines (six fallback cases). The collapsed mobile header stays 64 px high. Full-page open-panel scans marked contrast indeterminate where the overlay overlaps page text. A follow-up review composited the actual text alpha against the opaque panel background across 36 menu/appearance cases; minimum measured text contrast was 6.27:1, with no contrast violation. Closed-page audits cover the unobscured background.
- Native **Safari 26.6.2**: English/Arabic desktop and Responsive Design Mode at 320/390 px inspected. Connected Arabic, mixed-language specimens, layout, Light/Dark persistence, keyboard arrow selection and Escape focus restoration were checked. Reloading the updated source confirmed that section headings remain visible below the sticky header. The revised menu was also manually reviewed in native Safari at 320/390 px in English/Arabic, including open/closed state, language switching, Escape focus and section selection. Responsive Design Mode is emulation, not a physical-device test.
- The Safari review exposed delayed embedded-font wordmark painting. The four original editable SVGs remain byte-for-byte approved; previews/footer/PNG export now use matching font-independent paths derived from the approved vector PDFs. Existing SVG paths remain available, with revisioned site download links to avoid stale pre-Plex cache entries. Fidelity comparisons and visual review are recorded in `docs/brand-sources.md`.
- The accessibility review exposed three low-contrast icon download links on white cards in Dark/Black; the fixed links use approved deep teal. PNG control names now identify their asset. Body-font roles, original symbol geometry, palette tokens, icons, patterns and wallpaper files remain unchanged.
- All eight web fonts have the expected true weight classes, retained shaping tables and compliant modified family names. README/social artwork uses approved original R3 PNGs without redrawing.

Optional reproduction scripts are documented in the README. Machine-readable reports and screenshots are under ignored `.local/browser-review/{engine}/`, `.local/accessibility-review/{engine}/` and `.local/native-safari/`; navigation reports are under `.local/navigation-review/{engine}/`. No QA fixtures or evidence are part of Hosting.

## Exact release preparation and limitations

Candidate: **v0.2.0-beta.1**. `python3 scripts/prepare-release.py` requires a clean committed source tree and creates a static Hosting ZIP, deployment file hashes/configuration, exact target/scope, kit/checksums and beta release notes. It never deploys, tags or publishes. The public tree excludes scripts, docs, source vendors/PDFs, repository metadata, QA evidence, credentials and retired fonts; response security headers are unchanged. Intended GitHub attachments are `cave-brand-kit.zip` and `SHA256SUMS`, plus GitHub's tagged source archives. The kit contains **28 files**, about 5 MB, including original editable masters, matching web outlines and original TTFs/notices.

Physical iOS/Android devices, human VoiceOver/NVDA acceptance and a full accessibility audit remain unverified. Automated rule coverage and keyboard review do not establish full compliance. Firefox and WebKit results use installed Playwright browsers; native Safari was reviewed separately. Public HTTPS, live cache invalidation and production routing/headers/assets must be verified after a separately authorized rollout. Exact Hosting-emulator and live verification results are recorded with the release handoff. Live verification exposed the inherited extension-only cache rule missing clean HTML URLs; explicit no-cache rules now cover `/`, `/ar` and `/404`. This changes cache behavior only; security headers are preserved.

CI remains disabled. No paid services, credentials, security/access settings, repository ownership or Firebase ownership were changed. The verified beta was deployed and published after advance owner notification. Future deployment or publication still requires exact-artifact review and advance owner notification. The repository transfer remains the owner's separate action.
